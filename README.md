# autoapply — бот автоотклика на IT-вакансии

Ищет вакансии под профиль из `profile.yaml` на трёх площадках — **hh.ru**,
**Habr Career** и **getmatch**, — оценивает их по настраиваемым правилам, пишет
сопроводительное письмо под каждую вакансию через LLM и отправляет отклики.

Работает в два шага: `scan` собирает очередь и **ничего не отправляет**, `send`
отправляет то, что ты одобрил. Всё найденное пишется в SQLite, поэтому повторные
прогоны не дублируют отклики на одну вакансию.

## Что умеет каждая площадка

Это главное, что нужно понимать перед настройкой: **полный автоотклик есть только
у hh.ru**, потому что только у него есть официальный API для соискателя.

| Площадка | Поиск и письма | Автоотклик | Почему так |
| --- | --- | --- | --- |
| **hh.ru** | да, официальный API | **да** | OAuth и документированная ручка отклика |
| **Habr Career** | да, открытый API | по желанию, через cookie | официальный API только для работодателей: он читает отклики на *свои* вакансии, отправлять отклик соискателю нечем |
| **getmatch** | да, открытый API | по желанию, через cookie | публичного API нет вообще, вход только по одноразовому коду на email или в Telegram |

Для Habr Career и getmatch бот по умолчанию работает в режиме **«поиск + готовое
письмо»**: вакансия попадает в отдельную очередь со статусом `manual`, ты смотришь
её через `review --manual` и откликаешься по ссылке сам. Письмо уже написано —
остаётся скопировать.

Автоотклик на этих двух площадках можно включить (см. «Автоотклик на Habr Career и
getmatch»), но это обходной путь через cookie из браузера, и относиться к нему надо
соответственно.

## Быстрый старт

### 1. Зависимости

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. Ключ LLM

Скопируй `.env.example` в `.env` и заполни `OPENAI_API_KEY` (или
`ANTHROPIC_API_KEY`, тогда в `config.yaml` поставь `letters.llm_provider: anthropic`).

Без ключа бот не падает: письма берутся из шаблона `letters.template`, а в конце
прогона выводится причина. Какой источник использован, видно в колонке «Письмо»
команды `review`.

### 3. Первый прогон — без всякой авторизации

Habr Career и getmatch ищут без токенов, поэтому попробовать бота можно сразу:

```powershell
python -m autoapply scan --provider habr --no-letters --max-new 10
python -m autoapply review --manual
```

Это ничего не отправляет и ни к чему не подключается — просто показывает, какие
вакансии бот считает подходящими. Удобный способ настроить скоринг до того, как
тратить токены LLM и подключать hh.ru.

### 4. hh.ru: приложение, авторизация, резюме

Поиск и отклики в API hh.ru требуют OAuth-токена: без него `/vacancies` отвечает 403.

1. Зайди на https://dev.hh.ru/admin и создай приложение.
2. В настройках приложения укажи **Redirect URI**: `http://localhost:8765/callback`
3. В `.env` заполни `HH_CLIENT_ID` и `HH_CLIENT_SECRET`.

Redirect URI в `.env` и в настройках приложения должны совпадать символ в символ.

```powershell
python -m autoapply auth      # откроет браузер
python -m autoapply whoami    # покажет id резюме
```

Скопируй нужный id в `config.yaml` → `hh.resume_id`. Без него `send` не запустится.

### 5. Рабочий цикл

```powershell
python -m autoapply scan --max-new 10   # найти и оценить, ничего не отправляя
python -m autoapply review --full       # прочитать письма целиком
python -m autoapply send --limit 5      # отправить с подтверждением
python -m autoapply review --manual     # то, на что откликаемся руками
```

## Команды

| Команда | Что делает |
| --- | --- |
| `providers` | Какие площадки включены и готов ли автоотклик |
| `auth` | OAuth-авторизация на hh.ru, сохраняет токены в `data/tokens.json` |
| `whoami` | Аккаунт hh.ru и список резюме с их id |
| `scan` | Поиск, скоринг, генерация писем, наполнение очереди. Не отправляет |
| `review` | Очередь на отправку; `--manual` — вакансии для ручного отклика; `--full` — письма целиком |
| `send` | Отправка откликов из очереди; `--dry-run` только показывает |
| `status` | Счётчики по площадкам и статусам, расход суточного лимита |
| `requeue` | Вернуть в очередь отклики, упавшие по временной причине |

Полезные флаги:

- `--provider hh|habr|getmatch` — работать с одной площадкой. Есть у `scan`,
  `review`, `send`, `auth`.
- `scan --max-new N` — сколько новых вакансий добавить (по умолчанию 25).
- `scan --no-letters` — не тратить токены LLM.
- `scan --search "имя запроса"` — выполнить только один запрос.
- `send --limit N`, `send --yes` (без подтверждения), `send --dry-run`.

## Настройка

Всё поведение задаётся в двух файлах, код менять не нужно.

### `profile.yaml`

Профиль кандидата: опыт, навыки, достижения, контакты. Используется как контекст
для письма и как источник ключевых слов для скоринга.

Отдельно стоит блок `constraints.never_claim` — список того, чего LLM не должна
приписывать кандидату (чужой стек, руководство командой, senior-уровень). Промпт
запрещает выходить за рамки профиля, чтобы в письме не появился выдуманный опыт.

### `config.yaml`

**`providers`** — список включённых площадок, например `[hh, habr, getmatch]`.
Убери лишние, если какая-то не нужна.

**Запросы** задаются отдельно для каждой площадки, в её собственном блоке. Внутри
`params` пишутся **родные параметры этой площадки** — бот передаёт их в API как
есть, ничего не переводя. Так остаются доступны все фильтры платформы.

Незнакомый ключ в `params` бот заметит и предупредит: у площадок опечатка в имени
фильтра не вызывает ошибку, она молча меняет выдачу.

<details>
<summary><b>hh.ru</b> — параметры поиска</summary>

- `text` — поисковая строка, поддерживает `OR`, кавычки.
- `area` — регион: `113` Россия, `1255` Томская область, `90` Томск,
  `1259` Северск, `1` Москва, `2` Санкт-Петербург.
- `professional_role` — роли: `96` программист, `10` аналитик,
  `148` системный аналитик, `156` BI-аналитик, `150` бизнес-аналитик,
  `164` продуктовый аналитик, `165` дата-сайентист, `160` DevOps.
  Полный список: `GET https://api.hh.ru/professional_roles`.
- `experience` — `noExperience`, `between1And3`, `between3And6`, `moreThan6`.
- `schedule` — например `remote`. `period` — за сколько последних дней брать.

</details>

<details>
<summary><b>Habr Career</b> — параметры поиска</summary>

- `q` — поисковая строка.
- `skills` — числовые id навыков: `446` Python, `322` SQL, `537` PostgreSQL,
  `1349` FastAPI, `1241` PyTorch. Найти нужный:
  `GET https://career.habr.com/api/frontend/suggestions/skills?term=python`
- `qid` — уровень. Можно писать словами: `intern`, `junior`, `middle`, `senior`,
  `lead` (бот переведёт в id 1, 3, 4, 5, 6).
- `locations` — id городов: `c_736` Томск, `c_678` Москва, `c_679` Петербург.
  Найти: `GET https://career.habr.com/api/frontend/suggestions/locations?term=Томск`
- `remote: true`, `with_salary: true`, `salary` — минимальная зарплата,
  `employment_type` — `full_time` / `part_time`, `sort` — `date` / `salary_desc`.

Фильтр по `skills` точнее текстового поиска: `q: Python` находит любую вакансию,
где Python просто упомянут, включая роли из чужого стека.

</details>

<details>
<summary><b>getmatch</b> — параметры поиска</summary>

- `sa` — минимальная зарплата: `any`, `150000`, `200000`, `250000`, `350000`.
- `pa` — период публикации: `all`, `30d`, `7d`, `3d`, `1d`.
- `l` — локация и формат: `remote`, `moscow`, `saints_p`, `relocate`, `regions_ru`.
- `se` — уровень: `junior`, `middle`, `senior`, `lead`, `c_level`.
- `sp` — специализация: `python`, `data_science`, `data_analyst_bi`,
  `data_engineering`, `system_analyst`, `business_analyst`, `product_analyst`,
  `dev_ops`, `qa_auto` и другие.
  Полный список: `GET https://getmatch.ru/api/specializations`.

Кроме вакансий выдача getmatch содержит однодневные рекрутинговые события
(`one_day_offer`) — бот их отбрасывает, откликаться на них как на вакансию нельзя.

</details>

**`scoring`** — как отбираются вакансии. Правила общие для всех площадок:

- `reject_title_patterns` — безусловный отказ **по названию вакансии**. Основной
  инструмент отбора: название говорит, чем роль является, тогда как в описании
  перечислены десятки технологий.
- `blocklist` — безусловный отказ **по всему тексту**. Держи список коротким:
  «интеграция с 1С» — обычная задача автоматизатора, и отклонять из-за неё всю
  вакансию не стоит.
- `allow_seniority` — допустимые уровни из общей шкалы: `intern`, `junior`,
  `middle`, `senior`, `lead`. Каждая площадка приводит свой уровень к ней сама
  (hh.ru — из требуемого опыта, Habr — из Qualification, getmatch — из seniority),
  поэтому правило пишется один раз.
- `require_any` — хотя бы одно слово обязано встретиться, иначе вакансия не по профилю.
- `weights` — вклад каждого ключевого слова в балл (слово считается один раз).
- `bonuses` — доплата за удалёнку, указанную зарплату, домашний регион.
  Регион определяется по названию из `home_area_names`, а не по id: у площадок
  разные справочники регионов, а «Томск» пишется одинаково.
- `threshold` — порог принятия.

Все ключевые слова пишутся **в нижнем регистре**, это проверяется тестом.

Важно, как именно ищутся слова:

- `blocklist` и `reject_title_patterns` — **по границам слова**. Поэтому `java`
  отклонит «FullStack QA (Java)», но не тронет «JavaScript», а `c++` и `1с`
  находятся корректно.
- `weights` и `require_any` — **по подстроке**, чтобы работали основы слов:
  `автоматизац` находится и в «автоматизация», и в «автоматизации».

Настраивать скоринг удобно так: `scan --no-letters`, затем `review`. Если в очередь
лезет лишнее — добавь слово в `reject_title_patterns` или подними `threshold`. Если
хорошие вакансии отсеиваются, причина хранится вместе с вакансией и видна в `review`.

**`sending`** — `daily_limit` (у hh.ru свой лимит — 200 откликов в сутки),
`per_run_limit`, `delay_between` (пауза между откликами, секунды).

## Автоотклик на Habr Career и getmatch

По умолчанию выключен, и это осознанный выбор: у обеих площадок нет официального
API для отклика соискателя. Включать — на твоё усмотрение.

Что нужно понимать, прежде чем включать:

- Эндпоинты **не документированы** и могут измениться без предупреждения.
- Авторизация возможна только **cookie из твоего браузера**: у Habr Career вход
  закрыт reCAPTCHA, у getmatch — одноразовым кодом, API-ключей нет ни там, ни там.
- Habr Career может **потребовать капчу** на отклик. Бот распознаёт это, помечает
  вакансию как оставшуюся в очереди и прекращает отправку на этой площадке.
- Cookie живут ограниченное время, их придётся обновлять вручную.
- `robots.txt` getmatch закрывает `/api/`, а у Habr Career — путь откликов.

Если всё это устраивает:

1. Войди на сайт в браузере.
2. Открой DevTools → Application → Cookies и скопируй значения:
   - Habr Career: `remember_user_token` и `_career_session`
   - getmatch: `session`
3. Впиши их в `.env` (`HABR_REMEMBER_TOKEN`, `HABR_SESSION`, `GETMATCH_SESSION`).
4. В `config.yaml` поставь `habr.apply_enabled: true` и/или
   `getmatch.apply_enabled: true`.

Проверить готовность: `python -m autoapply providers`.

Вакансии, уже помеченные как `manual`, после включения автоотклика в очередь не
вернутся — они считаются обработанными. Новые пойдут в обычную очередь.

## Как это работает

```
scan:  запросы -> API площадки -> предфильтр по краткому описанию
       -> полное описание -> скоринг -> письмо (LLM)
       -> очередь: queued (можно отправить ботом) или manual (отклик руками)
send:  очередь -> отклик через API площадки -> sent / already / unavailable / failed
```

Предфильтр по краткому описанию отсекает явно чужие вакансии до того, как бот
потратит запрос за полным описанием и токены на письмо.

Письмо генерируется на этапе `scan` и хранится в очереди. Поэтому в `review` ты
видишь ровно тот текст, который уйдёт работодателю.

Откуда берётся полное описание:

- **hh.ru** — `GET /vacancies/{id}`, официальный API.
- **Habr Career** — разметка schema.org `JobPosting` на странице вакансии. Это
  открытый стандарт, рассчитанный на машинное чтение, и он надёжнее парсинга вёрстки.
- **getmatch** — `GET /api/offers/{id}`, поле `description`.

### Статусы вакансии

| Статус | Смысл |
| --- | --- |
| `queued` | прошла скоринг, письмо готово, ждёт отправки ботом |
| `manual` | письмо готово, но площадка не даёт откликаться из бота |
| `skipped` | не прошла скоринг |
| `sent` | отклик отправлен |
| `already` | отклик уже существовал |
| `unavailable` | архив, скрыта или требует тест — повторять бессмысленно |
| `failed` | временный сбой, можно вернуть в очередь через `requeue` |

`queued` и `failed` обрабатываются повторно, остальные считаются окончательными и
при следующем `scan` пропускаются.

## Ограничения

- **Отклик соискателя есть в API только у hh.ru.** Habr Career и getmatch такой
  ручки не публикуют — подробности выше.
- **Вакансии с тестом** через API hh.ru недоступны (`test_required`). Бот их
  отбрасывает на скоринге.
- **Суточный лимит** hh.ru — 200 откликов. Бот считает отправленное за сегодня и
  останавливается, а если лимит сообщит сам API, вакансия остаётся в очереди.
- **Схема ручки отклика hh.ru** убрана из публичной документации, и разные клиенты
  отправляют её по-разному. Поэтому первый отклик подбирает рабочий формат тела
  (form / JSON), а последующие используют найденный.
- Если одна площадка отвалилась (нет токена, сеть, сменился API), `scan` пишет
  причину и продолжает с остальными — собранная очередь не теряется.

## Добавить свою площадку

Реализуй интерфейс `JobProvider` (`autoapply/providers/base.py`: `search`,
`fetch_details`, `apply`, авторизация) и зарегистрируй класс в
`autoapply/providers/__init__.py`. Скоринг, письма, очередь и CLI не меняются — они
работают с провайдеро-независимой моделью `Vacancy`.

Если у площадки нет отклика через API, просто не переопределяй `apply`: базовая
реализация пометит вакансии как требующие ручного отклика.

Готовый HTTP-транспорт с троттлингом, ретраями и разбором ошибок — в
`providers/http.py`, разбор HTML и JSON-LD — в `providers/parsing.py`.

## Структура проекта

```
autoapply/
├── providers/              # Клиенты и адаптеры к площадкам
│   ├── base.py             # Базовый интерфейс JobProvider и модели
│   ├── http.py             # Общий HTTP-транспорт: троттлинг, exponential backoff, обработка 429/5xx
│   ├── hh_provider.py      # Официальный API hh.ru
│   ├── hh_auth.py          # Локальный OAuth2 сервер и хранилище токенов
│   ├── hh_client.py        # Клиент запросов к API со свежими токенами
│   ├── habr_provider.py    # Адаптер к Habr Career
│   └── getmatch_provider.py# Адаптер к getmatch.ru
├── cli.py                  # Консольный интерфейс (Typer + Rich)
├── config.py               # Загрузка и валидация config.yaml и окружения
├── matching.py             # Сопоставление требований вакансии и навыков
├── letters.py              # Генерация писем (OpenAI/Anthropic или шаблон)
├── scoring.py              # Скоринг: отсев неподходящих ролей и подсчет баллов
└── storage.py              # SQLite-хранилище вакансий и очереди откликов
tests/                      # 127 модульных тестов (unittest/pytest, моки, фикстуры)
```

## Тесты

```powershell
python -m pytest
```

127 тестов покрывают скоринг и поиск слов, конфигурацию всех площадок, генерацию
писем и деградацию в шаблон, хранилище и дедупликацию между площадками, разбор HTML
и JSON-LD, сборку параметров поиска для каждой платформы, разбор ответов API и
классификацию ошибок отклика. Сеть не используется — API заменён заглушками.

Тесты проверяют и сам `config.yaml`: что у каждой включённой площадки есть запросы,
что в них нет незнакомых параметров и что уровни в `allow_seniority` из общей шкалы.

## Секреты

`.env` и `data/tokens.json` содержат доступ к твоим аккаунтам и перечислены в
`.gitignore`. Токен hh.ru и cookie Habr Career / getmatch дают полный доступ к
аккаунту соискателя — не коммить их и не передавай третьим лицам. Файл токенов
создаётся с правами `0600`.
